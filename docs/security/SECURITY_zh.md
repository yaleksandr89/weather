请负责任地报告潜在漏洞。首先确定问题需要私密渠道，还是适合通过普通 Issue 报告。

## 应私下报告的内容

- 可能导致 WeatherAPI API 密钥出现在异常、调试输出或日志中的包行为。
- 可能将凭据或请求数据发送到非预期主机的包行为。
- 提供程序传输或响应处理中的漏洞，且具有具体安全影响，而不是一般的映射错误。
- 对本包有实质影响的可利用依赖项问题。
- 发布或源代码构件遭到破坏，或其他供应链问题。

## 可以在 Issues 中公开的内容

- 天气字段映射错误。
- 天气状况映射错误或不受支持。
- 不影响安全的验证错误。
- 与提供程序可用性或速率限制相关的行为。
- 文档问题。
- 功能请求。

## 如何报告

- 如果 GitHub 将来为此仓库显示私密漏洞报告表单，请优先使用该表单。
- 在没有私密表单期间，请创建一个最精简的公开 Issue，其中不要包含利用代码、API 密钥或敏感细节，并请求私密联系渠道。
- 在建立私密渠道之前，不要公开漏洞利用的技术细节。

## 应包含的内容

如有可能，请提供：

- 受影响的包版本或 commit SHA；
- PHP 版本；
- 受影响的提供程序：`Open-Meteo`、`WeatherAPI`、自定义提供程序或独立于提供程序的行为；
- 问题的影响；
- 最小复现；
- 相关时经过清理的请求或响应片段。

切勿包含真实的 API 密钥或其他机密。

## 后续处理

- 这是一个由一位作者维护的小型项目；维护者会尽力确认收到报告、复现问题并准备修复。
- 不保证 SLA。
- 不承诺提供漏洞奖励计划。
- 在修复可用之前，请协调技术细节的公开披露。
